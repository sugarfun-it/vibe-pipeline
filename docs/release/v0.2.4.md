## Fix

### Windows orphan TCP socket 導致 backend 起不來

PWA 觸發 `vbpl update` 走 `schtasks` 路線時,流程是:

1. 舊 backend 收 `POST /api/system/update`,`setTimeout(500ms)` 後 `server.stop(true)` + `process.exit(0)`
2. install.ps1 在 Task Scheduler service context 下跑:swap junction → `Start-Process bun "server start"` 起新 backend

實測 Windows + Bun 1.3.13 下,舊 backend 的 PWA keep-alive / SSE / poll 連線在 `server.stop(true)` 後 socket 沒有真正釋放 — 進入 `CloseWait` 狀態的連線(client side 已 close,server side 還沒)會被卡在 kernel TCP 表,**所屬 process 死掉後仍保留**。新 backend 試 `Bun.serve({ port: 3001 })` 直接 `EADDRINUSE` crash,PWA hangs 在「更新中…」。

orphan socket 的 owner PID 在 `netstat -ano` 看得到,但 `tasklist` / `Get-Process` / `taskkill` 全找不到 — admin PowerShell 也救不了。只能等 TCP keep-alive timeout(預設 Windows 7200 秒)、`Restart-NetAdapter` 強制斷網清空、或重開機。

### 動態 port fallback

`server/index.ts`:`Bun.serve({ port: DESIRED_PORT })` 包 try/catch,`EADDRINUSE` 改 `port: 0` 讓 OS 派閒置 port:

```ts
try {
  return Bun.serve(serveOpts);
} catch (e) {
  if ((e as { code?: string })?.code === "EADDRINUSE") {
    console.warn(`[server] port ${DESIRED_PORT} 被占用(orphan socket?),改用 OS 派閒置 port`);
    return Bun.serve({ ...serveOpts, port: 0 });
  }
  throw e;
}
```

bind 成功後寫 `~/.vibe-pipeline/server.json`(merge 既有 `repo_path` / `log_path`,蓋 `pid` / `port` / `started_at`),tmp + rename atomic 避免 CLI 同時寫的 partial read。

### CLI 從 `server.json` 讀 port

`cli/lib/serverBase.ts` `serverPort()` 加 fallback chain:

1. `VBPL_SERVER_PORT` env(明示 override)
2. `~/.vibe-pipeline/server.json` 的 `port`(backend 公告)
3. default 3001

sync 讀避免把 `serverPort()` 變 async 把 CLI 路徑全染色。

### PWA 不在乎 port

`src/api/_client.ts` 的 `API_BASE_URL` 是 vite env(預設空字串)→ relative URL → 跟 PWA 同 origin。backend 內部 port 怎麼換,PWA 都不需改 config / rebuild。

### Tailscale forwarding 由 user 自管

backend 不主動戳 `tailscale` CLI(Tailscale 不是必裝,通常只有要 SSL + PWA install 才用)。port 換了之後,有用 Tailscale 的 user 自己跑:

```bash
tailscale serve --bg --https=443 http://localhost:<actual-port>
```

`<actual-port>` 從 `~/.vibe-pipeline/server.json` 拿,或 `vbpl server status` 看。

## 升級

```bash
vbpl update                                      # CLI
# 或 PWA Settings → 立即更新
```

注意:若你的 prod backend 已經卡在 orphan socket 狀態(`vbpl server start` 報 `EADDRINUSE`),要先處理:

- 重開機(最乾淨)
- 或 admin PS 跑 `Restart-NetAdapter -Name "*" -Confirm:$false`(會斷網一兩秒)
- 或等 kernel 自己 timeout(Windows 預設兩小時)

清掉後 `vbpl update` 拉新版,之後再撞同樣問題 backend 會自動 fallback 不再 crash。
