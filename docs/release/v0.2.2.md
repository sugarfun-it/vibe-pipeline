## Fix

### Windows updater 改走 `schtasks`

實測 Bun 1.3.13 在 Windows 把 `Bun.spawn(detached, unref)` 的 child 全丟進帶 `KILL_ON_JOB_CLOSE` 的 job object。backend(被 `vbpl server start` 用此模式起)再 `Bun.spawn` child 全 100% 失敗:backend 500ms 後 `process.exit` → job close → mediator 連坐死,install.ps1 從沒機會啟動。

試過全死的方案:
- `Bun.spawn(powershell, detached: true)` — Node #51018 silently fail
- vbs + wscript — 偶 fail
- `Start-Process` mediator(v0.2.0 版本)— production 內 100% 卡
- `cmd /c start powershell` — cmd 中介死前未及 spawn
- WMI `Win32_Process.Create` via powershell — powershell 啟動 1-2s 慢於 backend exit

唯一可靠路線 `schtasks.exe`:50ms RPC 給 Task Scheduler service,task 由 service 創 install.ps1(完全在 backend job 外),50ms 在 backend exit 前完成。MS 自家 Chrome / Edge / Visual Studio / Adobe updater 也是同套模式,不是巧合。

具體改動:
- `server/lib/updater.ts`:Bun.spawn powershell mediator → 兩條 schtasks(`/create` + `/run`),task 命名 `VibePipelineUpdate`,`/tr` 用 `powershell -WindowStyle Hidden -File install.ps1` 直接跑(無 cmd 中介避免 console window 開整個 install 期間)
- `scripts/install.ps1` 開頭加 `Start-Transcript` 寫 `update.log`(取代原本 backend redirect,PWA 隱藏執行也有 log 可看)
- `scripts/install.ps1` 末段自呼 `schtasks /delete /tn VibePipelineUpdate /f` 自清,Task Scheduler GUI 不留 leftover
- backend 啟動時順手砍舊命名 task(`vp-update` / `vp-update-test`)兼容已升級的 enduser
