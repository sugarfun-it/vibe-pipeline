## Highlights
- **修掉「pipeline 跑完卻 0 個 commit、改動全不見」的隱性失敗** — 壞掉的 worktree(沒有 git 連結)會被誤當成可用,執行 AI 在裡面瞎跑、git 全失敗卻被當「沒改動」靜默略過,結果一個 commit 都沒有也不報錯。現在會偵測壞 worktree 自動重建,git 失敗也會明確報錯而非假裝成功。
- **「清理已合併 worktree」不再假報成功** — 之前資料夾被鎖或是孤兒清不掉時,還是會顯「已清除」;現在清完會複查資料夾真的不在,沒清掉就如實回報失敗。

## Fix
重用 worktree 時只看資料夾在不在、不檢查 git 連結是否健康,壞掉的資料夾被回收後執行 AI 在非 git 目錄裡跑、自己生出一堆假檔，而 commit 步驟把 git 失敗當成「沒改動」靜默跳過 → 整條 pipeline 0 commit 卻不報錯。三處一起修：重用前驗證 worktree 健康（壞了就重建）、git 失敗改為明確報錯、清理 worktree 後複查資料夾確實移除。
