## Highlights

- **install.ps1 不再假錯** — 手動 install 結尾 `schtasks /delete` task 不存在會吐 `exit 1`,污染 `$LASTEXITCODE`,外層 caller 誤判整段 install 失敗(實際已成功)
- **PWA 改 config 不再造半 init project** — `writeConfig` 只 mkdir `.vibe-pipeline/` 不 mkdir `pipelines/`,之後 `vbpl pipeline create` 撞 ENOENT
- **Windows CLI 多行 args 解法** — `vbpl ticket add/update` 加 `--{goal,prompt,acceptance}-file <path>`,值為 `-` 走 stdin,繞過 cmd shim 對多行 quoted args 的 mangle

## Fix

### `install.ps1` 結尾的假 exit 1

`scripts/install.ps1` 最後一段自呼 `schtasks /delete /tn "VibePipelineUpdate" /f *> $null` 自清。手動 install 走這條時 task 不存在,schtasks 寫 stderr `ERROR: The system cannot find the file specified.` 並 `exit 1`。`*> $null` 吞了 output 但**不會清 `$LASTEXITCODE`**,外層 caller(如 `irm | iex` wrapper 或 backend updater 看 `$LASTEXITCODE` 判斷)會誤判整段 install 失敗。

修法:`schtasks` 之後手動 `$global:LASTEXITCODE = 0` reset。PWA 觸發路徑因 task 真有被刪 exit 0,本來就沒事;手動 install 才會踩到。

### `writeConfig` 留下半 init project → `pipeline create` ENOENT

`pipelineDir.init()` 會一次建好 `.vibe-pipeline/{config.json, pipelines/, .runtime/}` 三層。但 PWA 走 Settings 改 project config 時呼 `pipelineDir.writeConfig`,該函式自己只 mkdir root + 寫 config.json,**不**建 `pipelines/`。

`hasInit()` 只檢查 root dir 存在,所以後續 `vbpl pipeline create` 通過 `requireInit` 但 `writePipeline` 寫 `pipelines/<id>.json` 撞 ENOENT。

修兩處:
- `writeConfig` 改走 `init()`(全 idempotent,call 多次無傷)再寫 config,確保 dir 結構完整
- `writePipeline` defensive `mkdirSync(dirname(file), recursive:true)` — 萬一還有別條野生路徑進來不會炸

### `vbpl project add` 對 fresh repo 沒提示下一步

`projectStore.open()` 只寫 `state.json` 把 project 加進 recent list,**不**建 `.vibe-pipeline/`(設計上 `add` ≠ `init`)。fresh repo user 看不到 hint,以為 `add` 完就能直接 `pipeline create`,踩 `NOT_INITIALIZED`。

修:`add` 後若 `hasInit=false` 印兩行提示,指 `vbpl project init --here` / `--project-path <path>` 下一步。

## Feature

### `ticket add/update` 加 `--*-file` flag + stdin 支援

Windows `vbpl.cmd` shim → `bun run vbpl.ts %*` 走 `cmd.exe %*` 參數展開,對 PowerShell 來的多行 quoted args(here-string、`@'...'@` 等)會吃掉換行。長 `--prompt` / `--acceptance` 透過 shim 就壞,只能 bypass shim 直接 `bun run`,DX 差。

加三條新 flag:

| flag | 行為 |
|---|---|
| `--goal-file <path>` | 從檔讀 goal |
| `--prompt-file <path>` | 從檔讀 prompt |
| `--acceptance-file <path>` | 從檔讀 acceptance(一行一條) |

值為 `-` 走 stdin(只能一個 `*-file` 用 `-`,stream 只能消費一次)。配合 `Get-Content prompt.md \| vbpl ticket add ... --prompt-file -` 流式餵入。

順手:
- `cli/lib/args.ts` parser 接受 bare `-` 當 value(Unix 慣例),否則 `--prompt-file -` 會被當 boolean flag
- `acceptance` 拆分改 `[;\r\n]+` 同時支援 inline `a;b;c` 與檔內一行一條
- TICKET USAGE / error 文案明示「單條 acceptance 免分隔」「多行用 *-file」,避免被誤導成必須分號 hack
