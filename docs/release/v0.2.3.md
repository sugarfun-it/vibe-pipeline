## Highlights

- **install.ps1 不再假錯** — 手動 install 結尾 `schtasks /delete` 不存在 task 吐 `exit 1`,污染 `$LASTEXITCODE`,外層 caller 誤判失敗。
- **PWA 改 config 不再造半 init project** — `writeConfig` 改走 `init()`,確保 `pipelines/` 也被建。
- **Windows CLI 多行 args 解** — `vbpl ticket add/update` 加 `--{goal,prompt,acceptance}-file <path>`,值 `-` 走 stdin,繞過 cmd shim 對 quoted multiline args 的 mangle。

## Fix

### `install.ps1` 假 exit 1

`schtasks /delete` 後手動 `$global:LASTEXITCODE = 0` reset。PWA 路徑 task 真被刪不會觸發,只手動 install 踩到。

### `writeConfig` 半 init

`pipelineDir.writeConfig` 改走 `init()`(idempotent),確保 dir 結構完整;`writePipeline` 補 defensive `mkdirSync` 兜底。

### `vbpl project add` hint

`add` 後若 `hasInit=false` 印兩行 hint 指向 `vbpl project init`,避免 fresh repo user 直接 `pipeline create` 踩 `NOT_INITIALIZED`。

## Feature

`vbpl ticket add/update` 新 flag:

| flag | 行為 |
|---|---|
| `--goal-file <path>` | 從檔讀 goal |
| `--prompt-file <path>` | 從檔讀 prompt |
| `--acceptance-file <path>` | 一行一條 |

值為 `-` 走 stdin(只能一個 `-`)。例:`Get-Content prompt.md \| vbpl ticket add ... --prompt-file -`。

## 升級

vbpl update
