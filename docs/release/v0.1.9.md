## Fix

- **`swapCurrentTo` 拆 link 噴 EFAULT**:`rmSync(junction, {recursive:true})` 在 Windows 對 junction 噴 `EFAULT: bad address in system call argument`(Bun fs bug)。連鎖:swap 失敗 → 沒重建 junction → 沒 `clearPending` → `.pending` 永久殘留,下次 start 進無限 retry 圈
- 修法 = 抽 `removeLinkEntry` helper:Windows junction 用 `rmdirSync`(junction 是 directory reparse point,rmdir 移 link 不 recurse target),POSIX symlink 用 `unlinkSync`,一般 dir 才 `rmSync recursive` fallback。第 8 輪驗實證 same-name swap 看起來 work(因 promote 已正確覆蓋 + junction target 同名),但 versioned target 換新 tag 時這條 path 會炸到使用者
